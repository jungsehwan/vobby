# readycommit — 커밋 전 코드 정리·검토

**대상은 커밋 예정 diff만** (`git diff` + `git status`의 신규 파일). 기존 코드 전체를 건드리지 않는다.
이 스킬은 **커밋하지 않는다** — 3단계 통과 후 `/commit` 스킬로 넘긴다.

## 0. 변경 범위 파악
- `git status --short` + `git diff` 로 이번 커밋 예정분 확정
- 문서(.md)만 변경된 경우: 1단계(주석)·3단계(컨벤션)는 건너뛰고 2단계를 문서 정합성 검토로 대체

## 1. 불필요한 주석 제거

**제거 대상:**
- 코드가 이미 말하는 것을 반복하는 주석 (`// 사용자를 생성한다` 위에 `createUser()`)
- 작업 과정의 잔재 (`// 수정됨`, `// 여기 추가`, `// 기존 코드 대체`)
- 주석 처리된 죽은 코드 블록
- 담당자·기한 없는 방치성 TODO/FIXME (필요하면 tech-debt-tracker.md로 옮기고 제거)

**보존 대상 (제거 금지):**
- 코드로 표현 불가능한 제약·이유 설명 (예: "Kakao는 이메일 미제공 케이스가 있어 nullable")
- Design/Plan 문서 참조 주석 (예: `(design §0-1)`)
- 좌표 규약·단위 등 데이터 계약 설명

판단 기준: **"이 주석을 지우면 다음 독자가 잘못된 코드를 짤 수 있는가?"** — 아니오면 제거.

## 2. 코드리뷰 (버그 중심)

diff를 정독하고 다음 관점으로 결함을 찾는다. 발견 시 **직접 수정**하고 수정 내역을 보고한다:
- 논리 결함: 경계값, null/undefined 처리, 시간대(timestamptz 규약), 동시성
- 에러 처리: 실패가 조용히 삼켜지는 곳 (DESIGN.md §6 — catch 후 무시 금지)
- 멱등성: 재시도·중복 실행 시 안전한가 (QUALITY.md §4)
- 리소스 누수: 커넥션/리스너/파일 핸들 해제
- 보안: 시크릿 평문, 인젝션 가능 지점 (SECURITY.md 해당 항목)

확신이 없는 발견은 수정하지 말고 사용자에게 보고만 한다.

## 3. 코드 컨벤션 검증 (docs/DESIGN.md 대조)

- §2 명명: TS(컴포넌트 PascalCase.tsx, 그 외 kebab-case.ts, NestJS `*.entity/service/controller.ts`) / Python(snake_case, 타입 힌트)
- §3 배치: 워크스페이스 간 직접 상대경로 import 금지 (`packages/*` 경유)
- §5 데이터 접근: 컨트롤러 직접 쿼리 금지, 공간 쿼리는 전용 리포지토리 격리
- §7 설정: 시크릿 평문 금지 — `.env.example`엔 키 이름만
- 새 패턴 도입이 보이면: DESIGN.md 갱신이 함께 있는지 확인 — 없으면 지적

## 4. 마무리
1. 수정을 적용했다면 컴파일 재검증: `npm run typecheck --workspaces --if-present` (+ Python 변경 시 `compileall`)
2. 결과 보고 형식:
   ```
   주석: 제거 N건 / 보존 판단 N건
   리뷰: 수정 N건 (내역), 보고만 N건
   컨벤션: 위반 N건 수정 (내역)
   재검증: typecheck {통과|실패}
   ```
3. 커밋은 하지 않는다 — "이어서 /commit 하시겠습니까?"로 마친다
