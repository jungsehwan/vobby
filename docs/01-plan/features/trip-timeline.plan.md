# 여행 타임라인 — 갤러리 EXIF 역구성 (trip-timeline)

> Status: Draft (승인 대기)
> 작성일: 2026-09-01
> 배경: 2026-09-01 제품 방향 정정 — 직접 기록(⛔ mobile-gps-logging) 폐기, 소싱으로 전환

## 1. 배경 / 현재 동작 (코드 근거)

### 1.1 기존 프로세스
- 앱은 현재 "기록 시작/중지" 화면 + 백그라운드 위치 태스크 + 세션 기반 사진 스캔 — **전부 폐기 대상 전제 위에 있음**
- 재사용 가능 코드 (media-exif-timesync에서 승계):
  - EXIF 추출·좌표 우선순위(EXIF>근사>미매칭)·`INSERT OR REPLACE` 멱등 패턴 (`media-scan.service.ts`)
  - expo-sqlite 로컬 저장 체계, Maestro/simctl/EXIF 주입 검증 체계

### 1.2 폐기 대상 (이 기능의 선행 작업)
- `src/features/recording/` 전체, 기록 화면, expo-location/expo-task-manager 의존성, 위치 권한 문구·UIBackgroundModes (사진 권한만 남김)
- 로컬 sessions/points 스키마 → trips/trip_media로 교체

## 2. 사용자 요구 (원문 요약)
"이미 위치정보를 저장했던 소스에서 받고, 해당 일자와 시간, 위치정보를 토대로 갤러리 내 사진으로 여행 타임라인과 숏폼을 자동으로 만든다" (2026-09-01).

## 3. 범위 / 비범위

### 범위 (In scope)
- 기록 기능 완전 제거 (코드·권한·의존성)
- **갤러리 스캔 → 여행(Trip) 자동 클러스터링**: EXIF 시각·GPS 기반 — 시간 간격/거리 기준으로 사진들을 여행 단위로 묶음
- 여행 목록 화면(자동 구성, 기간·사진 수·지역 요약) + 여행 상세(시간순 타임라인: 사진 + 시각 + 좌표)
- 여행의 궤적 근사 재구성: GPS 있는 사진들의 시간순 좌표 시퀀스 (LineStringZM 규약 — 업로드/숏폼의 입력)
- 로컬 스키마: trips / trip_media

### 비범위 (Out of scope)
- 구글 타임라인·GPX import → 기능 4b `location-import`
- 서버 업로드, 숏폼 생성 요청, 지도 시각화
- 블러/중복 필터 (마일스톤 3 유지)

## 4. 요구사항 상세

### 4.1 여행 클러스터링 규칙 (Design에서 파라미터 확정)
- 시간순 사진 나열 후 분리 기준: **연속 사진 간격 > N시간**(기본 8h — 숙박·이동 경계) 또는 날짜 경계 옵션
- 최소 구성: 사진 M장 이상(기본 3장)만 여행으로 승격 — 일상 스크린샷 잡음 배제
- GPS 없는 사진도 시각으로 여행에 포함 (좌표는 여행 내 시간 근접 사진에서 근사 — 기능 5 로직 승계)

### 4.2 스캔
- 최초 스캔: 갤러리 전체(사진만) — 진행률 표시. 이후 증분(마지막 스캔 시각 이후)
- 멱등: asset_id 기준 upsert, 클러스터링 재실행 시 여행 재구성(사용자 수정 개념은 추후)

## 5. 방어적 AC
- 사진 권한 거부/제한(limited): 안내 + 크래시 없음
- 사진 수천 장: 스캔이 UI를 블로킹하지 않고 진행률 표시, 중단 후 재실행 시 이어짐
- GPS 있는 사진 0장인 여행: 타임라인은 시각만으로 표시 (좌표 없음 허용)
- EXIF 시각 없는 사진: creationTime 폴백 (기능 5와 동일)

## 6. 오픈 이슈 / 결정 대기

- 여행 수동 편집(병합/분리/이름) — MVP 이후
- iOS limited 권한(선택 사진) UX
