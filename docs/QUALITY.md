# Code Quality Grading

Evaluator 에이전트가 구현 결과를 검증할 때 사용하는 기준.

<!-- 그레이딩 프레임(등급·빌드 필수·검증 절차)은 Stack에서 그대로 이관.
     점수 항목은 웹(Entity/Controller 등) 기준이었으므로 플랫폼 중립 카테고리로 재구성함.
     앱 스택 확정 후 각 항목의 세부 체크를 구체 컨벤션으로 치환할 것. -->

## 그레이딩 등급

| 등급 | 설명 |
|------|------|
| A | 모든 기준 충족, 프로덕션 준비 완료 |
| B | 핵심 기능 동작, 경미한 개선점 있음 |
| C | 기본 기능 동작하나 누락/문제 있음 |
| F | 빌드 실패 또는 핵심 기능 미동작 |

---

## 1. 빌드 (필수 통과)

| 항목 | 기준 |
|------|------|
| 빌드 | {빌드 명령} 성공 |
| 컴파일/타입체크 경고 | 새로 추가한 코드에 경고 없음 |

빌드 실패 = 무조건 F등급.

---

## 2. 도메인/데이터 계층 (30점)

### 데이터 모델 (10점)
- [ ] 프로젝트 베이스 모델/명명 규칙 준수
- [ ] nullable/옵셔널 필드 올바른 처리
- [ ] 스키마 변경 시 마이그레이션/문서 동기화

### 저장소·서비스 (20점)
- [ ] 데이터 접근과 비즈니스 로직 분리 (UI에 로직 없음)
- [ ] 에러 처리 적절 (실패가 조용히 삼켜지지 않음)
- [ ] 성능 함정 없음 (반복 쿼리, 메인 스레드 블로킹, 대량 데이터 OOM)

---

## 3. UI 계층 (30점)

- [ ] 프로젝트 화면 구조/상태관리 패턴 준수
- [ ] 로딩/빈 상태/에러 상태 처리
- [ ] 기존 공용 컴포넌트 재사용 (중복 구현 금지)
- [ ] 접근성·플랫폼 가이드라인 기본 준수

---

## 4. 견고성 (20점) — Stack 6차원 감사에서 이관

- [ ] 논리 결함 없음 (경계값, 시간대, 동시성)
- [ ] 멱등성 (재시도/중복 실행에 안전)
- [ ] 오프라인/네트워크 실패 시 동작 정의됨 (앱 특성상 필수)
- [ ] 리소스 누수 없음 (리스너/구독/파일 핸들 해제)

---

## 5. 검증 완성도 (20점)

- [ ] Design 문서 대비 갭 없음 (범위 항목 전수 대조)
- [ ] 실행 검증 수행 (실기기/시뮬레이터에서 화면·동작 확인)
- [ ] 회귀 없음 (변경이 기존 기능을 깨지 않음)

---

## 리포트 형식

```
등급: {A|B|C|F}
점수: {합계}/100
빌드: {성공|실패}
갭: {Design 대비 미구현/변경 항목}
지적: {심각도순 발견 사항}
```
